# Foot pedal box

**English** · [Українська](README.uk.md)

<p align="center"><img src="images/finish.jpg" width="440" alt="The finished box: twelve jacks, twelve LEDs, one USB cable"></p>

Twelve foot-pedal inputs for a PC, built around the controller board of a used Genius USB keyboard.
Each input is a 6.35 mm mono jack for a momentary tattoo pedal. 
Pressing a pedal lights that channel's LED and, through an optocoupler, presses one of F1-F12 on the keyboard matrix.
On the PC, keyd turns those keys into Ctrl+Alt+Shift+F1..F12 and REAPER scripts bound to them switch guitar amp tracks.
Whatever is left over is free for game binds.

## Story

The box exists to change guitar tones in REAPER without taking a hand off the guitar: one tone per pedal, up to twelve of them.
Ready-made USB foot switches (the PCsensor kind that the `footswitch` tool programs) offer one to three switches for real money: a triple one like the [FS323-P](https://prom.ua/ua/m-7539015935706131995-fs323-trojnaya-usb.html) is listed at 2,250 UAH on prom.ua, so twelve switches that way would be about 9,000.
Tattoo pedals are the opposite: sturdy metal momentary switches with a 6.35 mm mono plug on a stock cable, for a fraction of the price.
All they need is something to plug into.

<p align="center"><img src="images/ready-made-fs323-p.jpg" width="300" alt="FS323-P: a ready-made triple USB foot pedal, 2,250 UAH"></p>

<p align="center">
<img src="images/pedal_front.jpg" width="40%" alt="A tattoo pedal: steel body, momentary switch, 6.35 mm mono plug on a stock cable">
<img src="images/pedal_back.jpg" width="40%" alt="The underside: four rubber feet and the switch screws">
</p>

That something is the old Instructables recipe [A Foot Pedal for the Computer Keyboard](https://www.instructables.com/A-Foot-Pedal-for-the-Computer-Keyboard/): take a USB keyboard apart, keep the controller PCB, and close the matrix contacts of a key with a switch.
This build changes two things about it.

- **Nothing touches the matrix directly.** Each pedal closes a 5 V loop through a PC817 optocoupler, and the phototransistor presses the key.
The pedal cables are galvanically isolated from the controller, every channel gets a status LED in series for free, and since a phototransistor conducts one way only, pedals cannot ghost each other the way membrane contacts can.
- **The keys are F1-F12, and keyd rewrites them.** The box enumerates as an ordinary keyboard, so without a remap every pedal would collide with the real keyboard.
A per-device keyd config turns each F-key into a Ctrl+Alt+Shift chord that nothing else types.

The first case layout put all twelve jacks on one long side with the LEDs next to them.
The final one splits the jacks six per side, one row per case shell, and moves the LEDs to the top where they are visible from above.
The first case considered (Sanhe 11-4, 100 x 68 x 50 mm) turned out too small for twelve jacks; the D150B at 148 x 92 x 68 mm with removable end panels is what got built.

## How it works

![Schematic](pedal-box-schematic.png)

Editable source: [pedal-box-schematic.drawio](pedal-box-schematic.drawio).
The file is generated by [gen-schematic.pl](gen-schematic.pl), see [Regenerating](#regenerating).

Pedal down closes a 5 V loop: `+5V -> 220R -> LED -> PC817 input -> jack tip -> pedal switch -> jack sleeve -> GND`.
The LED lights, and the PC817 phototransistor shorts the key's two matrix lines exactly like the original key did.
The matrix only ever sees the transistor (about 0.2 V drop), so scanning is untouched, and the pedal cable is galvanically isolated from it.

Never put an LED in series with the matrix contact itself: its forward voltage eats the logic margin and the scan pulses are microamps anyway.

The power LED (D13) sits straight across USB 5 V through 1k and is on whenever the port is powered, which on many desktops includes soft-off.

### Measured connector pins

Pins of the keyboard's membrane connector that produce each key, measured by shorting pairs with a wire while watching `sudo keyd monitor`.

| Key | pin a (collector) | pin b (emitter) |
|-----|-------------------|-----------------|
| F1  | 2                 | 25              |
| F2  | 3                 | 25              |
| F3  | 3                 | 20              |
| F4  | 3                 | 22              |
| F5  | 16                | 26              |
| F6  | 6                 | 22              |
| F7  | 7                 | 20              |
| F8  | 7                 | 25              |
| F9  | 13                | 25              |
| F10 | 13                | 26              |
| F11 | 13                | 22              |
| F12 | 13                | 24              |

Keys share lines, so only 11 pins are wired: 2, 3, 6, 7, 13, 16 (sense lines) and 20, 22, 24, 25, 26 (scan lines). 
Eleven wires run from the controller to the opto board, not 24.

### Circuit notes

- Sense vs scan: with the board powered, the pad of a pair that idles near VCC is the sense line (collector), the pulsed one is the scan line (emitter).
The table assumes the first number is sense.
If a sense pin idles low instead, swap collector and emitter on all twelve optos the same way.
Wrong polarity only means no key event, nothing breaks.
- Resistors: 220R gives about 8 mA through a red, yellow or green LED plus the opto input.
Blue or white LEDs leave no headroom at 5 V.
For the power LED alone, 330R is bright and 1k is dim with red, yellow or green.
- LED polarity: anode toward +5V (through the resistor), cathode toward the opto anode.
PC817 pins: 1 anode, 2 cathode, 3 emitter, 4 collector.
- Keep the controller PCB intact and its USB cable; tap VBUS and GND where the cable lands on the PCB.

## Software

### keyd

The box enumerates as the original keyboard (Holtek, USB id 04d9:1702).
On NixOS, `nix/modules/system/pedal/default.nix` in the dotfiles gives it its own keyd config, which is what the host actually runs:

```nix
services.keyd.keyboards.pedal = {
  ids = [ "04d9:1702" ];
  settings = {
    # A held macro key starts repeating after this; at ~25 days it never does.
    global.macro_timeout = 2147483647;
    main = {
      f1 = "macro(C-A-S-f1)";
      f2 = "macro(C-A-S-f2)";
      # ...
      f12 = "macro(C-A-S-f12)";
    };
  };
};
```

[keyd/pedal.conf](keyd/pedal.conf) is the same thing as a plain keyd file for a non-Nix machine.
An explicit id beats the `*` default config, so the board gets only this file.
Two things are going on in it:

- **A macro instead of a remap.** The controller holds the key down for as long as the foot is on the pedal, and the compositor turns that into auto-repeat, so a REAPER action bound to a plain key would fire over and over.
`macro(...)` presses and releases the chord once when the pedal goes down and does nothing more until it comes up; the huge `macro_timeout` stops the macro itself from repeating.
- **Ctrl+Alt+Shift+F1..F12, not F13..F24.** F13-F24 look like the obvious free keys, but they do not survive the trip: the default xkb map turns FK13..FK23 into XF86Tools/Launch/Touchpad keysyms, and REAPER's SWELL only translates F1..F12 to begin with.
A three-modifier chord collides with nothing a keyboard types, and Shift keeps Ctrl+Alt+Fn from being read as a VT switch.

The same module installs `footswitch`, the programmer for PCsensor-style USB pedals, which this box does not need.

### REAPER

`reaper/Scripts/amp-switch/` in the dotfiles holds `amp_1.lua` through `amp_12.lua` and `amp_cycle.lua`.
A copy is kept here under [reaper/amp-switch/](reaper/amp-switch/) for the record; REAPER loads the ones in the dotfiles.
Each `amp_N.lua` arms exactly the N-th track whose name starts with `GT_` (record arm plus input monitoring) and unarms the other `GT_` tracks, so one pedal is one amp chain.
`amp_cycle.lua` alternates between two of them from a single pedal.
The home-manager guitar module links the directory into REAPER's resource path so the scripts show up under ReaScript: Load; the key bindings themselves are assigned once per machine in the Actions list, because REAPER rewrites `reaper-kb.ini` on exit and keeping it in the repo would fight it.

### Probing notes

Learned while finding the matrix pins:

- keyd classifies a device as a keyboard only if it has the letter keys or a media key.
The board's "System Control" USB interface (power, sleep, wake) has neither, so keyd ignores it and logind reads it directly.
Shorting the wrong trace can shut the PC down.
For a probing session hold an inhibitor first:
  `systemd-inhibit --what=handle-power-key:handle-suspend-key:handle-hibernate-key:handle-reboot-key --who=pedal sleep 7200`
- `keyd monitor` cannot see devices the daemon has grabbed; it shows the virtual keyboard's output instead, which is fine for finding keys.

## Regenerating

The schematic, after editing the generator:

```sh
perl gen-schematic.pl > pedal-box-schematic.drawio
drawio --export --format png --scale 1.5 --border 10 --output pedal-box-schematic.png pedal-box-schematic.drawio
```

Edits made by hand in draw.io are lost on regeneration, so either edit the
generator or stop regenerating once the hand edits start.

The sketch SVGs, after editing the FreeCAD file (headless, no GUI needed):

```sh
FC_OUT=images/sketches freecadcmd gen-sketches.py
```

The PNGs next to them are `pdftoppm -r 150` renders of the three PDFs.
